# 研判评分卡 · 完整规格（约定4 权威副本）

> 本文件是 agent.md 约定4 的**完整规则**，由 PRED 1 从 agent.md 抽出集中维护；
> agent.md 约定4 只保留触发条件 + 指针 + 一页速查表。后续所有对评分卡的修改都改这里。

> **outside view 优先（总纲）**：先问「历史上这类事情发生的频率是多少」，再问「这次有什么不同」。
> 顺序反了就会系统性过度自信——纯 inside view 的预测者最易患的错，就是把叙事说服力当成预测价值。
> 置信度必须从基准率出发做调整，不得凭空给出。

## 详细规则

### 1. 方向判断
看多 📈 / 看空 📉 / 中性震荡 ➡️（带 emoji）。须是明确方向，不得只写「震荡偏多」不带期限。

### 1.5 基准率（outside view · 必填，先于置信度）
| 项 | 内容 |
|---|---|
| 无条件基准率 | 该标的历史上 N 日内达成本判断幅度的频率 = __%（n=__，95%CI [__,__]） |
| 条件基准率 | 在类似条件下（条件描述：______）频率 = __%（n=__，CI [__,__]） |
| 本次调整 | 置信度 = 条件基准率 __% ± __，理由：______ |
| 差异可证伪性 | 如果 ______ 不成立，则本次不特殊，应回落到基准率 |

**硬规则**：
- 置信度必须从基准率出发做调整，**不得凭空给出**。
- 单次调整幅度 >20pct 时，必须在报告中单列一节说明为什么本次如此特殊，并给出该「特殊性」的可证伪条件。
- 基准率算不出来（样本不足 / 数据缺失）时，置信度上限 60，并注明「无基准率锚定」。

计算工具：`tools/base_rate.py`、`tools/baseline.py`、`tools/pattern_hitrate.py`。

### 2. 置信度
0–100 **整数分**（不用「偏高/偏低」等模糊词）；且 = 三情景中主情景概率。

**置信度来源唯一性（防量纲混用）**：只能来自三情景主情景概率，严禁直接引用 pattern_score / 各类指数值 / 子智能体自报置信度。

**从基准率出发**（见 1.5）：置信度 = 条件基准率 + 调整，调整须有可证伪理由。

**超额命中率视角**：本体系的命中率必须与基准比才有意义。复盘核心指标 = 本体系命中率 − max(random_dir 命中率, ma_rule 命中率)。
- 超额 > +5pct 且 n≥30 → 「体系有效」
- 超额在 ±5pct → 「与基准无显著差异」
- 超额 < −5pct → 「⚠️ 体系跑输基准，当前配置为负 alpha」
- n < 30 → 「样本不足（n=__），暂不评价」

**校准后置信度**（见 PRED 9）：展示两个数 —— 原始 62 / **校准后 55**（基于历史 n=__ 条的校准曲线）。
**仓位按校准后的数映射**，不按原始值。样本不足（n<30）时校准后 = 原始值。

**置信度硬上限**（取三者最小值）：
```
最终置信度上限 = min(
    D7 数据质量上限,          # 数据层 TASK 4
    可预测性硬上限,            # 第 11 项
    基准率无锚定时的 60        # 第 1.5 项
)
```

### 3. 期限
明确持有期 —— 5日 / 20日 / 60日 / 具体季度（如 2026Q4）。

### 4. 幅度区间
目标价区间或涨跌幅区间，如 +5%~+15% 或 区间[28,34]。

> **量纲校验（必过）**：本项必须通过 `tools/sanity_check_card.py`。
> 区间宽度应在 1–3 倍期间波动率（σ_p）之间；不通过（R1<1.0 或 R1>3.0）的评分卡不得入台账——
> 区间设计错误会被误记为判断错误，污染校准曲线。

### 5. 证伪位
什么价位/信号出现说明看错（止损位），如「跌破1400 认错」。

> **量纲校验（必过）**：本项必须通过 `tools/sanity_check_card.py`。
> 证伪位距现价应 ≥1.5 倍期间波动率（σ_p）；不通过（R2<1.5）的评分卡不得入台账——
> 过近的证伪位会制造假止损，并把噪音误记为「判断错」。

### 5.5 更新触发器（必填，不得写「视情况而定」）
| 项 | 内容 |
|---|---|
| 下次检验时点 | YYYY-MM-DD（什么数据 / 事件，须来自第0步 D0 的数据日历） |
| 若 A 发生 | 置信度调至 __ （A 要具体到数值阈值） |
| 若 B 发生 | 置信度调至 __ |
| 若 C 发生 | 直接认错平仓 |

**硬规则**：
- 三个分支的条件必须互斥且穷尽（覆盖所有可能结果）。
- 阈值必须是数字，不许写「明显走弱」「大幅超预期」这类无法机械判定的词。
- 「下次检验时点」必须早于预测期限，否则等于没有中途检验。

### 6. 三情景概率（离散分布 · 由情景树聚合）
三情景各自带一个**价格/收益区间**，构成离散概率分布：

| 情景 | 概率 | 收益区间 | 代表值（区间中点） | 触发路标 |
|---|---|---|---|---|
| 牛 | 25% | +12% ~ +25% | +18.5% | ____ |
| 基准 | 55% | −3% ~ +8% | +2.5% | ____ |
| 熊 | 20% | −15% ~ −4% | −9.5% | ____ |

- 三个区间不得重叠，且应大致连续覆盖（不留大空隙）。
- **三情景概率必须由情景树末端路径聚合得出**，并附 `tools/scenario_tree.py` 的输出；不得脱离情景树独立拍定。
- 复盘用 CRPS（连续概率评分）+ Brier（方向二元）并列；CRPS 越小越好。

### 7. 建议仓位
由**校准后**置信度映射 —— <60 不动 / 60–70 轻仓 / >75 标准仓 / 上限封顶（计入 A股 T+1、涨跌停、滑点）。
若共识矩阵落左上角（共识+已定价），仓位强制「不动·仅记录」，无论置信度多高。

### 8. 凝练逻辑
看多 / 看空**各 1–3 条**核心驱动，每条 **≤20 字**；末尾加 **一句话总结**（核心矛盾/胜负手）。

### 9. 已定价检查
一句话区分「这是市场共识（已在价格里）」vs「这是与共识的差异（variant perception，只有这部分值得下注）」。

### 10. 市场先验（仅宏观/事件类必填，个股类填「不适用」）
宏观/事件类判断必须给出 **Polymarket 对应市场赔率** + 自身置信度与该赔率的偏差 + 一句话差异理由。
复盘统计「与市场共识（赔率）分歧的预测」命中率 = 真正的 alpha 读数。

### 11. 可预测性评级（决定置信度硬上限）
| 评级 | 典型问题 | 置信度硬上限 |
|---|---|---|
| 高 | 央行 3 个月内政策方向、有预测市场对照的二元事件、财报发布日程类 | 85 |
| 中 | 宏观状态 3-6 个月延续性、产业周期位置、供需缺口方向 | 75 |
| 低 | 60 日商品/个股方向、单季财报是否超预期、板块轮动次序 | 65 |
| 接近随机 | 5 日内个股方向、单日涨跌、消息驱动的短期波动 | 55 |

**判定依据必须写出来**：该时间尺度上是否有回测证据或公开研究支持存在可预测性。拿不出依据的，一律按「低」处理。

**若评为「接近随机」**：必须在回复开头直接告诉用户 ——
「这个问题在这个时间尺度上接近不可预测，任何高置信判断都是过度自信。以下分析只提供结构性理解，不构成方向性押注依据。」

### 12. 共识矩阵定位（共识 × 市场定价，二维交叉验证）
评分卡必须写明落在哪一格：

|  | **与市场共识一致**（Polymarket/期权隐含/卖方一致预期/期货曲线） | **与市场共识背离** |
|---|---|---|
| **专家内部共识** | 🔵 高置信、**零 alpha** → 只作背景，不下注 | ⭐ **最高价值格** → 内部一致但市场未定价，这才是该建仓的 |
| **专家内部分歧** | 🟡 需判断是我们错还是市场错 → 补数据后重判 | ⚪ 低置信、信息不足 → 观望 |

- 落格：____（左上/右上/左下/右下）
- 市场定价读数来源与数值：____
- 若落左上角（共识+已定价），仓位强制「不动·仅记录」，无论置信度多高。

### 13. 红队结论（第13位专家 · 对抗性终审）
- 红队找到的最强反证：____
- 最脆弱环节：____
- 置信度调整：红队找到 ≥1 个主分析**未考虑过**的强反证 → 置信度 −10；找到的反证主分析已考虑并有回应 → 不调整；红队未找到有力反证 → 不加分（共识过度一致反而是风险信号）。
