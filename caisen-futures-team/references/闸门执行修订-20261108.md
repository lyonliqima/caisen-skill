## 一、R1｜时间闸按「计划持有期」分档（替换 ≥90 天一刀切）

### 1.1 原条款错在哪

旧清单闸门 3 ①：距自然人/法人最后平仓日 **≥90 天**，60–90 天只减不加、<60 天禁止建仓。该阈值来自 M-H18/M-H19 的**长期持有多头**场景（要扛展期收益、要滚月），与「持有 3–5 日的波段空单」不是同一个问题。且旧文混用「天」与「交易日」，口径未声明。

### 1.2 修订判据（**口径一律为交易日，必须在报告声明**）

| 计划持有期 | 距自然人/法人最后平仓日下限 | 附加条件 | 判定 |
|---|---|---|---|
| **≤5 日**（事件 / 波段试仓） | **≥20 个交易日** | 覆盖持有期 + 5 日离场缓冲 + 换月窗口 | 通过 |
| **20 日**（波段） | **≥45 个交易日** | 完整换月窗口；且接续合约须过 R2 流动性闸 | 通过 |
| **60 日及以上 / 长持 / 需滚月** | **≥90 个交易日** | 保留 M-H18/M-H19 原口径 | 通过 |
| **<20 个交易日** | — | — | ⛔ **硬否决**（见 R2 第 2 节，唯一保留的时间硬闸） |

**判定顺序**：先由结论评分卡的「期限」字段确定计划持有期 → 再查对应分档 → 最后报出「距死线 X 个交易日 / 要求 Y / 判定 ✓·✗」。**禁止先套 90 天再反过来解释持有期。**

**日期口径**：自然人最后平仓日按交易所公告取，报告须写「以交易所最新公告为准」；交易日数用交易日历计算，不得用自然日折算。

### 1.3 理由与实锤

- 实锤：65/65 主力 <90 天，但其中大量合约仍有 30–60 个交易日，足够覆盖 ≤5 日波段；旧闸把「不能长拿」误判成「不能碰」。
- 来源：`_runs/shortscan_20261108/scan.json` 的 `days_left` / `deadline` 字段，数据日 2026-11-06。

## 二、R2｜风险成本化：从 AND 布尔否决改为 penalty 计分

### 2.1 原条款错在哪

旧清单零节 2、第二节用法、第四节主理人规则均写「任一 ✗ 即降级为观望·不出方向」「闸门 3 为前置硬闸」。六道闸门里大部分是**证据强度问题**（成本理由成不成立、席位有没有方向性、位置口径冲不冲突），不是**能不能下单**的问题。把证据强度问题做成布尔否决，等于要求「所有证据都完美」才允许有观点——这在真实市场里恒为假。

### 2.2 修订：方向分与可开仓分分离，风险标成扣分

**两个分数必须同时报出，禁止只报一个**：

- `direction_score`（0–100）：方向偏空/偏多的证据强度，**不受标的可交易性影响**。
- `exec_score`（0–100）：今日实际可扣扳机的分数，由 `direction_score` 经 penalty 计算：

```
exec_score = clamp(0, 100, direction_score × Π m_i − Σ p_i)
```

| 编号 | 触发条件 | 乘性 m |
|---|---|---|
| G1 | 破成本四问未过却仍把「成本支撑」当建仓理由 | 0.85 |
| G3-t | R1 分档不达标（但未 <20 交易日） | 0.50 |
| G3-l | 成交 < 主力 5% 或持仓 <2 万手 | 0.40 |
| G3-c | 到接续合约年化租 >5% | 0.70 |
| G3-s | 期限结构 `contango>5%` 或 `deep_back>5%` | 0.50 |
| G4-a | 60 天内第 2 次同向且**无**「上次错在哪」段落 | 0.50 |
| G4-b | 该品种存在逾期未结算台账记录 | 0.80 |
| G5 | 位置三口径 gap ≥25pp（位置因子失效） | 0.80 |

| 编号 | 触发条件 | 减性 p |
|---|---|---|
| P-rr | 真实入场价下 RR <1.0 | −10（并对 `direction_score` 先 ×0.75） |
| P-fill | 挂单为左侧挂单 / 当日非交易日 / 无法成交 | −10 |
| P-na | **数据不可得**（席位双边总量、期限结构等） | −5 |

**关键口径修正**：
1. **「数据不可得」≠「证据 ✗」**。闸门 6 席位数据拿不到时只扣 5 分、该证据不计票，**禁止**把 533/533 的缺失当成全市场一票否决。
2. **闸门 2（政策 3 日回吐 >70%）保留对「该条理由」的永久作废**，但**不再否决整个结论**——换其他独立证据支点即可继续，报告须写明「已剔除该理由」。
3. **每道 penalty 必须逐项列在报告里**（编号 + 是否触发 + 扣分），禁止只给一个总分。

### 2.3 唯一保留的三条硬否决（真·不可执行）

| 硬否决 | 判据 |
|---|---|
| H1 时间 | 距自然人/法人最后平仓日 **<20 个交易日** |
| H2 成交 | 无报价 / 停牌 / 涨跌停封板无法成交 / 交易所限制开仓 / 接续合约同样无流动性 |
| H3 数据 | 数据新鲜度阻断，关键价格无法追溯到「来源 + 时间戳」 |

**除 H1–H3 外，任何闸门 ✗ 都不得直接输出「观望·不出方向」。** 违者视为未过第 6.5 步提交前自检。

### 2.4 理由与实锤

- 实锤：533 → 369 → 70 → 12 → 0；单独放松任意 1 道软闸仍为 0，说明 AND 结构本身塌缩，不是某一道太严。
- 实锤：旧口径下 `exec_score` max = 4.3/100，分数失去了区分度（与旧清单第一节「分辨率 0.0139」是同一类病）。
- 来源：`_runs/shortscan_20261108/scan.py` 第 240–368 行、红队复盘 memory 2026-11-08。

## 三、R3｜显式可开仓阈值 + 禁止硬编码结论

### 3.1 阈值表（结论必须由分数推导）

| `exec_score` | 输出态 | 允许的动作 |
|---|---|---|
| **≥60** | 可开仓 | 标准仓位建议，**单品种 ≤3% 名义**；须给入场 / 止损 / 目标 / 证伪位 / 结算日 |
| **45 ≤ x < 60** | **可证伪试仓**（见 R5） | 仅 ≤1% 试仓，且须 `direction_score ≥60`、`RR ≥1.5` |
| **<45** | 观望 | **必须写「距离开仓还差什么」**：缺哪几项 penalty、各要改善多少分才到 45/60 |

**报告必须同时给出 `direction_score` 榜与 `exec_score` 榜**，并用一段话解释两者背离原因（方向偏空 ≠ 今日可开仓）。

### 3.2 ⛔ 禁止硬编码结论（新增硬规则）

1. 报告 Hero 区、核心结论、「今日是否建仓」文案，**必须由 `max(exec_score)` 与 3.1 阈值比较后程序化生成**，格式：
   ```
   hero = f"结论：{state}｜全市场最高可开仓分 {max_exec:.1f}/100（{best_sym}）｜阈值 60"
   ```
2. **任何报告模板 / `gen_report.py` 里不得写死**「零新建空单」「今日不建仓」「无合规合约」等结论串。出现即视为模板违规，报告作废重生成。
3. 若 `max(exec_score)` 确实 <45 而输出「观望」，**仍须列出 R3.1 要求的改善清单**；只写「零新建」不写改善清单 = 不合格。
4. 本规则与 `caisen-10-experts-analyst` 第 5 步「收敛铁律」、第 6 步「综合研判评分卡」并列：结论必须明确、可证伪、可入台账，**且必须可追溯到分数**。

### 3.3 理由与实锤

- 实锤：`_runs/shortscan_20261108/gen_report.py` 第 89 行把「零新建空单（含远月）。现在不下单，11/09 也不扣扳机」写死在模板里；全文搜不到 `exec_score >= X` 的判定。也就是说，**即使某天出现 exec_score=80 的标的，报告仍会输出零新建**。这是最严重的一处：结论与数据完全解耦。
- 来源：`output/期货做空研判-20261104.html`、`output/期货做空研判-20261108.html` 连续两篇同结论；37/44 篇历史报告含「禁止新建 / 不扣扳机 / 无合规合约」类措辞。

## 四、R4｜破解台账自锁环

### 4.1 原条款错在哪

旧清单 1.3 第 2 条：「同一品种存在逾期未结算记录时，**不得给出该品种的新方向判断**」。叠加 142 条逾期、352 条 open，使闸门 4 覆盖 72.2% 合约；而「零新建」结论又不产生任何可结算记录 → 欠账只增不减 → 覆盖只会更高。这是**正反馈死锁**。

### 4.2 修订四条

1. **开工仍先跑** `python3 predictions-ledger/score.py --due`（保留旧纪律），但**「批量结算」与「出本轮判断」解耦**：不得因存在历史欠账而停止本轮分析。
2. **逾期不再禁止出方向**，改为 `exec_score ×0.80`（G4-b），且报告必须写明「该品种历史逾期 n 条，本轮结算计划日期 YYYY-MM-DD」。
3. **禁止把「未结算」当「证据为 ✗」**：未结算只影响置信度校准权重，不影响标的可交易性判断。
4. **每次输出「观望」也必须落一条可结算台账记录**：组合型/宽基结论用 `market-data-cache/FUTPOOL.csv` 等权指数作价格基准（最新 982.7818，2026-11-06），单品种结论用该合约收盘价；必须带 `entry_price`、期限、方向、证伪位，否则到期无法结算、继续喂大自锁环。

### 4.3 理由与实锤

- 实锤：台账 437 条 / 352 open / 仅 32 条有 `actual_return` / 142 条逾期；`score.py --calibration` 显示 50–60 与 60–70 桶均被收缩（Brier 0.3224、resol 0.1013）。
- 实锤：`P-20261108-001` 是首次为「组合型零动作结论」补上 `FUTPOOL.csv` 价格快照的可结算记录，可作为模板复用。
- 来源：`predictions-ledger/ledger.jsonl`、`predictions-ledger/append.py`、`market-data-cache/FUTPOOL.csv`。

## 五、R5｜≤1% 可证伪试仓出口（打破二值输出）

### 5.1 三态输出（替换旧的「出方向 / 观望」二值）

| 态 | 触发 | 约束 |
|---|---|---|
| 可开仓 | `exec_score ≥60` | R3.1 |
| **可证伪试仓** | `45 ≤ exec_score <60` 且 `direction_score ≥60` 且 `RR ≥1.5` | 见 5.2 |
| 观望 | 其余 | 必写改善清单 + 必落台账（R4.2 第 4 条） |

### 5.2 试仓纪律（全部为硬约束）

1. 仓位 **≤1% 名义**（单品种），不得加仓、不得摊平。
2. 止损 = 常规止损距离 **×0.6**（更严），持有期 **≤5 个交易日**，到期无条件平仓。
3. 必须写明：**证伪位、结算日期、失效条件、入场价来源+时间戳**。
4. 必须落台账并标记 `trial=1`，到期由 `score.py` 自动结算，用于恢复 Brier / 分辨率校准回路。

### 5.3 理由与实锤

- 实锤：连续「观望」使框架 32/n 的结算覆盖率无法改善，置信度桶永远缺样本；试仓是**用最小成本买回可证伪性**，不是放宽风控。
- 实锤：反事实筛选中 UR2705（RRadj 2.99）在新口径下浮出，说明阈值 45–60 区间有真实标的，不会恒为空。

## 六、执行顺序（替换旧清单第五节口诀）

> **一结算清单（不阻断本轮）、二定持有期、三算方向分、四把风险标成扣分、五对阈值、六落台账。**

```
① python3 predictions-ledger/score.py --due       # 列欠账，不停工
② 由评分卡「期限」定持有期 → 查 R1 分档（报交易日数）
③ 过 H1–H3 硬否决；H 命中 → 该标的出局，其余继续
④ 算 direction_score（证据强度，与可交易性无关）
⑤ 逐项套 R2 penalty → exec_score，逐项列扣分明细
⑥ 对 R3.1 阈值 → 生成 Hero/结论文案（禁止硬编码）
⑦ 无论哪一态，落一条可结算台账记录；观望也落（R4.2）
```

**旧口诀**「一算账、二破成本、三看政策留痕、四查合约能不能做、五问上次错在哪、六除席位总量、七单合约重算位置」保留为**证据检查清单**，但不再作为**否决链**使用。
