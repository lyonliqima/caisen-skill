# 波动率口径 · 事件倒查 · 同源去重：三条可机械执行的校验（2026-09-17 立）

> 来源：2026-09-17「涪陵电力 600452」十二专家实盘跑通（台账 P-20260917-001）。
> 三条都是**主分析一轮全员漏掉、被红队第 13 席或独立复算捕获**的问题，
> 且共同点是：**都不是「数据错了」，而是「口径/类别表/计票规则」本身不完整**——
> Q 闸门（数据对不对）与 E 闸门（有没有大事被漏）都查不出来，因为它们不是事实错误，是**方法论缺口**。
> ⚠️ 只学 M-W 步骤，不抄任何方向性结论。

## M-W1｜σ 估计窗口律：**σ 的估计窗口必须与预测期限匹配**（最高优先级，已落到代码）

### 症状
「证伪位设在现价的 ±6%，是 1.5σ，很宽松」——听起来对，**但 σ 是哪一段时间算出来的？** 没人写。

### 为什么致命
σ 不是品种的常数，是**当前波动制度**的读数。当品种刚经历一段暴涨/暴跌再进入横盘，
用**固定长窗口**（如 250 日）估 σ，会把**已经结束的旧波动制度**残留进来，得出一个远高于当下的 σ，
于是：
- 幅度区间被误判「过窄」→ 逼你把区间放大到荒谬宽度
- 证伪位被误判「过近」→ 逼你把止损推到永远不会触发的地方
- **结果是「看对了却被记成错」，污染整条校准曲线**

### 2026-09-17 涪陵电力（600452）实锤（同一张卡、同一批价格，只换 σ 口径）

| σ 口径 | 日 σ | σ₂₀ | 证伪距离比 R2 | 判定 |
|---|---|---|---|---|
| 近 20 日窗口（**期限匹配**） | 0.933% | **4.17%** | 1.50 | ✅ pass |
| EWMA λ=0.94（≈11 日半衰期） | 1.439% | 6.44% | 0.97 | ❌ fail |
| 近 60 日窗口 | 2.174% | 9.72% | 0.64 | ❌ fail |
| **近 250 日窗口（旧版默认）** | **2.764%** | **12.36%** | **0.51** | ❌ fail |

**同一张评分卡，在四种口径下「通过 / 不通过」直接翻转。**
250 日口径要求的证伪位距离是 **±18.5%**——对一个当前日波动不足 1% 的标的，
等于要求「止损设在 7.43 或 10.81」，**这不是风控，是放弃风控**。
根因：250 日窗口掺入了 2026 年 3–6 月该股从 16 元跌到 8.6 元的崩跌段（日 σ 高达 5–7%）。

### 三条硬规则

**M-W1-a｜期限匹配**：给 W 日预测，就用近 W 个日收益估 σ（`lookback = clamp(W, 20, 250)`）。
> 给 20 日预测用近 20 日；给 60 日预测用近 60 日。**期限与窗口同长**是短周期里最不易被操纵的选择。

**M-W1-b｜多口径并报**：任何写 σ 的报告必须同时给出 **match / EWMA(0.94) / 250 日** 三个 σ_p 及其 R2。
**只报一个 σ 而不声明口径 = 无效声明。**

**M-W1-c｜制度切换告警**：当 `σ_match / σ_250` 落在 **[0.67, 1.50]** 之外，必须在报告中显式声明
「本判断的量纲对 σ 口径敏感，采用 X 口径，理由是 Y」。
> 比值 <0.67 = 刚经历过高波动后转平静（**旧波动会虚增 σ**，本次 0.34）；
> 比值 >1.50 = 波动正在放大（**旧窗口会低估 σ**，此时反而要用更长的窗口/EWMA）。

### 工程落地（2026-09-17 已改）
`tools/sanity_check_card.py` 旧版固定 250 日窗口 → 已重写：
- 默认 `--sigma-mode match`（期限匹配）；可选 `ewma` / `window` / `conservative` / `legacy`
  - `conservative` = max(match, ewma, 250)，用于「宁可要求更远止损」的场合
  - `legacy` 仅用于**历史卡重算**，不得用于新卡
- 新增 `--falsification-low` 支持**双侧证伪位**分别校验（旧版只校验上侧）
- 输出新增 `sigma_p_pct_by_basis` / `r2_by_basis` / `verdict_by_basis` 三张对照表
- 价格四舍五入容差 `R2_EPS=0.005`（避免把 ±1.5σ 边界上的 0.3% 报价舍入误差判成失败）
- 复算命令：
  ```
  python3 tools/sanity_check_card.py --symbol 600452 --period-days 20 \
      --current 9.12 --target-low -0.0406 --target-high 0.0307 \
      --falsification 9.69 --falsification-low 8.55
  ```

> **反向教训（自我批评）**：本轮主分析**没经过这个工具**就用 55 日日 σ（2.201%）推出 σ₂₀=9.84%
> 并自设 10.11 为「1.5σ」——实际是 2.59σ。红队复算后修正为 8.55 / 9.69。
> **主分析手算的 σ 竟然比工具默认值更接近正确**，说明错的不是人，是工具。**

## M-W2｜E 闸门的关键词类别表必须含「排期」类（2026-09-17 补第 ⑤ 类）

### 症状
公告倒查跑满了（2 页 60 条）、四类关键词（再融资 / 股权激励 / 治理变更 / 分拆并购）全部通过，
于是写出结论：**「事件催化真空」**。

### 为什么错
前述四类关键词**全是「已发生的重大资本动作」**。而**「未来某日有确定事件」这条信息，
只出现在标题最平淡的日常公告里**——业绩说明会、路演、预约披露日、除权除息日、
股东会/董事会决议的**实施期限**。**类别表缺一类，等于该类别永远不被查。**

### 2026-09-17 涪陵电力实锤
- E 闸门已跑：`data_notice` 倒查 2 页 60 条，覆盖 2025-12-25 ~ 2026-09-15
- **漏掉**：公告编号 **2026-025**《关于召开 2026 年半年度业绩说明会的公告》
  - 时间：**2026-09-22（周二）16:00–17:00**，上证路演中心
  - 出席人：总经理蔡彬、董秘兼财务总监刘薇、副总经理张文智、独立董事刘伟
  - **投资者提问预征集窗口 09-15 ~ 09-21 16:00**（即「漏掉时它已经在进行中」）
  - 该节点**恰落在 20 日预测窗口内**
- 后果：报告与台账都写了「事件催化真空」，方向被错误地按「无催化剂」定价

### 强制动作——窗口内排期扫描（写入 E 闸门 A 节，作为第 ⑤ 类）
公告倒查的**同时**必须回答：**「预测窗口 [T, T+W] 内，有没有已经排好期的确定性事件？」**
逐项列出、写入「先行指标跟踪清单」首位：

| 类型 | 公告标题关键词 | 为什么必查 |
|---|---|---|
| 业绩说明会 / 路演 | 业绩说明会、投资者关系活动记录表、路演 | 唯一给出「未来确定日 + 管理层当面问答」的场合；提问预征集窗口=市场预期已被定向收集 |
| 定期报告 | 年度报告、半年度报告、季度报告、预约披露时间、变更预约 | 决定窗口内是否有财报落地 |
| 权益分派 | 除权除息日、股权登记日、分红实施 | 决定价格是否会被机械调整 |
| 解禁 | 限售股上市流通、解禁 | 决定窗口内是否有确定性抛压 |
| 承诺到期 | 增持计划、回购计划、股权划转、同业竞争承诺 | 承诺期到期日常是「动作窗口」 |
| 指数 / 交割 | 指数调样、期货交割日 | 被动资金与实物交割的确定时点 |

> **引用硬规则**：写「事件催化真空」这句话之前，必须能列出「已逐项检查上表六类，窗口内无排期事件」。
> **不能列出 = 不能写「真空」。** 「真空」是一个**穷尽性结论**，穷尽性结论必须给出穷尽性证据。

## M-W3｜同源冲击去重律：证据计票前先做「冲击源归并」

### 症状
证据卡里出现三条看似独立、方向一致的空头证据，于是计票「空 3」，权重被放大。

### 为什么错
如电力板块：**「来水偏丰 → 水电出力增 → 火电需求降 → 煤价下行」**——
这是一**条**因果链，不是**三件**独立的事。把它拆成三张卡计票，
等于**把同一个信息重复计入三次**，人为制造「证据一边倒」。
同理：
- 「原油跌 → 石脑油跌 → 乙烯跌 → PVC 成本塌」= 一条链
- 「地产新开工跌 → 螺纹需求跌 → 铁矿跌」= 一条链
- 「美元涨 → 人民币贬 → 铜进口成本升」= 一条链

### 判定规则（M-W3 三步）
1. **问一句**：这两张卡里，**有没有一张是另一张的原因**？有 → 同源，**必须归并**
2. **归并后重新计票**，且**归并只在计票层做，证据卡本身保留**（保留可追溯性，但不重复加权）
3. **报告里写出归并清单**：`证据卡 A/B/C 同源（A → B → C），计票按 1 条计`

> **判据速查**：若把其中一张卡删掉，另一张卡的**方向**会不会跟着翻转？会 → 同源。
> 不会（只影响幅度）→ 独立。

## M-W4｜「事件停滞」的量能印记：等待博弈怎么被认出来

### 症状
一只股在同一个价位附近横盘两个月，成交量持续萎缩，有人说「缩量整理，蓄势待发」，
也有人说「无人问津，要阴跌」。

### 怎么区分：看**待定事件的成交额印记**（涪陵电力实锤）
- 事件公告日附近（07-21）：成交额 **9.31 亿**（换手 6.04%）
- 停滞 56 天后（09-16）：成交额 **2.34 亿**（换手 1.67%）
- **萎缩 −74.9%**

**读法**：一件事悬而未决（如股权划转「尚未收到股东方进展函告」），
市场会形成 **waiting game**——**任何一方先动都要付出成本，于是双方都不动**，
成交额随等待时长单调萎缩到某个地板并**停在那里**。
- 印记 = **价格不动 + 量能单边萎缩到地板 + 事件方零进展**
- 与「缩量整理蓄势」的区别：**蓄势者的事件状态是「推进中」，等待者的事件状态是「停滞中」**
- **交易含义**：等待博弈里**没有方向**，只有「谁先让步」。
  故正确输出是 **区间 + 条件触发**，而不是方向；证伪位必须**双侧对称**（任一方向被打破都说明博弈结束）

> ⚠️ 不得把「量能萎缩」直接读成利多（变盘向上）或利空（无人问津）——
> **量能萎缩只说明「均衡」，方向由打破均衡的第一次放量决定。**

## M-W5｜沙箱内取 A 股长历史日 K（工程法）

沙箱对行情 API 有硬性限流，东财 `push2his` 直接 `RemoteDisconnected`。
**实测可用的替代通路**：

```
https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=<code>,day,<start>,<end>,<count>,qfq
```
- `<code>` 带市场前缀：`sh600452` / `sz000001`
- 返回 `data.<code>.qfqday`（前复权）或 `.day`（不复权），每行 `[日期, 开, 收, 高, 低, 成交量]`
- **⚠️ 单次最多返回 640 根**（请求 2000 也只给 640）→ **必须分段+合并**：
  ```
  以 end 逐段前移：end=2026-09-16 → 2024-01-26 → 2022-01-26 → 2020-06-01
  取并集去重（后写覆盖先写），实测 4 段合并得 1871 根（2019-01-02 ~ 2026-09-16）
  ```
- 落盘用 `tools/save_kline.py --symbol 600452 --stdin-json '<{"nodes":[...]}>'`
  → 写 `market-data-cache/<symbol>.csv`，供 `tools/baseline.py`（三基准）
  与 `predictions-ledger/append.py`（自动回填 `entry_price` / `entry_ma20`）消费
- **先取数再开口**：`entry_price` 未固化 = 到期无法算 `actual_return` = 复盘闭环断掉
