# 证据协议（Evidence Protocol）

> **纯规则文件 · 九专家体系所有搜集到的信息一律落「证据卡」，后续分析只引用卡片 id。**
> 配套 `source-tiers.md`（信源分层 T1–T4）。本文件是「数据层」的唯一真相来源，凡与本文件冲突的取舍一律以本文件为准。

---

## 一、证据卡字段定义

**每条搜集到的信息 = 一张卡**（一条新闻 / 一条公告 / 一条研报观点 / 一条舆情 / 一条 Polymarket 赔率 = 一张卡）。字段如下：

| 字段 | 规则 | 示例 |
|------|------|------|
| `id` | `E001`、`E002`… 顺序编号，供评分卡与报告引用 | `E007` |
| `claim` | 一句话主张，**≤30 字** | 美联储9月降息概率升至68% |
| `quote` | 原文关键句摘录（带引号的最关键一句，用于人类回溯核验） | “委员会认为通胀路径仍需观察” |
| `origin` | 原始出处（通稿归一后的**真正一手来源**，见第二节） | 财新 / Reuters / 巨潮资讯 / Polymarket |
| `via` | 抓取通道：`mx-search` / `news-agg` / `WebSearch` / `股吧` / `alphaear` | `mx-search` |
| `tier` | `T1`–`T4`（见 `source-tiers.md`） | `T2` |
| `url` | 可点击链接（溯源用） | `https://...` |
| `published_at` | `YYYY-MM-DD HH:MM +0800`，**禁止相对时间** | `2026-07-10 09:35 +0800` |
| `retrieved_at` | 检索时刻，`YYYY-MM-DD HH:MM +0800` | `2026-07-13 16:05 +0800` |
| `direction` | `利多` / `利空` / `中性` / `背景` / `反向` | `利多` |
| `topic` | 关联维度：标的本体 / 美元 / 资金流 / 政策 / 地缘 / 情绪 / 商品 / 大盘 … | `资金流` |

**`direction` 取值说明**：
- `利多 / 利空 / 中性 / 背景`：常规四类。
- `反向`：**仅用于反向搜索得到的反方证据卡**（见第0步第5项门槛），表示「与初步方向相反的论据」。

---

## 二、去重规则

1. **同一事件只留 1 张卡**：标题主体实体 + 事件动词相同，或正文首段高度重合 → 归为同一事件，只保留一张代表卡（合并不同 origin 到 `via` 列表）。
2. **通稿归一**：文内标注「来源：XX」或明显为通稿转载的，`origin` 写**原始媒体**（真正一手），`via` 里列出所有转载通道（`mx-search` / `news-agg` / `WebSearch` 都算）。
3. **「多源印证」重定义**：≥2 个**独立 `origin`** 才算多源印证；同一通稿的不同转载**不计为独立票**（转载不计票）。
4. **反向卡独立成卡**：反向搜索结果单独成卡，`direction` 标 `反向`；未发现反方时仍记 1 张「未发现有力反方证据」卡（见第0步）。

---

## 三、时间戳硬规则

- **数据层一律绝对时间**，含日期 + 时区，格式 `YYYY-MM-DD HH:MM +0800`。
- **禁止**在卡片任何字段写「X 小时前 / 刚刚 / 昨日 / 前天」等相对时间。相对时间**只允许在最终报告展示层**出现（如「12 小时前」用于人类阅读），但溯源真相仍以绝对时间为准。
- **反面案例（必读）**：见 `news-aggregator-skill/MISTAKES.md` 的 **「WallStreetCN Timestamp Ambiguity」** 条目——把 Unix 时间戳格式化成 `HH:MM` 丢失了日期，导致 AI 把「09:35」误算成「1h ago」（实际 12h 前）。教训：数据层必须保留完整日期时区，**展示层再决定如何呈现**。

---

## 四、落盘约定

- 第0步结尾**按本协议把全部搜集结果落为证据卡**，写进 `_run/evidence-<日期>-<主题>.md`（Markdown 表格，每行一张卡，列顺序同第一节）。
- **后续第 1–5 步只引用卡片 `id`**（如 `E001` / `E007`），不重读原文。
- 报告里**每条核心结论都必须能点回证据表某张卡 `id`**；评分卡「看多/看空」每条逻辑也必须对应到卡 `id`（含反向卡）。
