# 背景包规范（B 包 · v1 · 2026-10-15 立）

> **定位**：本文件是 `caisen-10-experts-analyst` 的**背景料供应链规范**，对应 SKILL.md **第0步·第0.1条**。
> 它管的是「**开工前桌上有没有最新鲜的料**」；不重复管「料对不对」（那是 Q 闸门的活）、
> 「料够不够」（那是第0步数据质量门槛 8 项的活）。
>
> **一句话**：把「每天定时收背景 → 校验新鲜度 → 不是最新就重跑 → 12 专家共用」这条流水线，
> 从人工纪律变成**有产物、有闸机、有执行者**的机制。

## 一、为什么单立一层（问题陈述）

立此规范前，框架的状态是**「有制度、没闸机」**：

| 已有零件 | 位置 | 为什么不够 |
|---|---|---|
| 保鲜期规则 | `references/数据时效与准确性闸门-20260913.md` Q-T2 | 位于 **第1.5步**——分析**已经开跑之后**才查，过期了前面几步的时间已经花掉 |
| 预取缓存 | `market-data-cache/` | 设计意图写明「每天跑一次、分析时读缓存」，但 **`cache/` 目录实测从未产出过**；`latest.py` 只按文件 mtime 取最新一份，**不判过期** |
| 定时任务 | WorkBuddy 自动化 | 6 个活跃任务**全是「出分析」，没有一个「备料」** |
| 12 专家共享背景 | —— | 背景数据散在 5 个各管各的目录（`market-data-cache/`、`mi-analysis/.cache/`、`stock-screener/cache/`、`predictions-ledger/market-data-cache/`、`references/_cache/`），**无单一入口** |

**后果**：一份 8 月的缓存丢在那里，`latest.py` 照样返回、分析照样开跑，
Q-T2 那张表拦不住任何东西——因为**闸门长在流程中段，而不是门口**。

## 二、制品契约

### 2.1 落盘位置

```
$CAISEN_ROOT/_runs/briefing/
├── 2026-10-15.json      # 机读版（12 专家与脚本消费）
└── 2026-10-15.md        # 人读版（用户与报告引用）
```

- **一个交易日一份**，文件名 = **数据日**（不是生成日）。同日重跑**覆盖**，不追加。
- 背景包**不存原始大数据**，只存「结论字段 + 溯源指针」——原始数据留在各自源目录，
  背景包负责**指路 + 记录取数状态**，避免双份真相。

### 2.2 JSON 契约

```json
{
  "date": "2026-10-15",
  "generated_at": "2026-10-15T16:20:00+08:00",
  "builder": "briefing-prefetch@v1",
  "expected_data_date": "2026-10-15",
  "overall": "full | partial | failed",
  "layers": {
    "<layer_key>": {
      "status": "fresh | stale | missing | n/a",
      "as_of": "2026-10-15",
      "source": "market-data-cache/cache/2026-10-15.json",
      "payload": {},
      "reason": "取数失败原因（status != fresh 时必填）"
    }
  },
  "degraded_layers": ["B_macro"],
  "notes": []
}
```

**硬字段**：`date` 必须存在且为 `YYYY-MM-DD`（`freshness_check.py` 依赖它判新鲜度）；
`status != fresh` 的层**必须填 `reason`**，不得静默留空。

### 2.3 层划分与取数分工

分层的唯一依据是**沙箱能不能取到**——这条线决定谁来跑。

| 层 | 内容 | 取数通路 | 执行者 | 保鲜期 |
|---|---|---|---|---|
| **A 行情数值** | A1 大盘指数/板块/资金流；A2 期货期限结构三件套（月差/基差/仓单+前20席）；A3 汇率与外盘锚 | `market-data-cache/fetch_daily.py`（东财→新浪→腾讯）；郑商所官方文件 + 新浪期货日K；`westock-mcp data_quote` | **本机 crontab**（沙箱对行情 API 实测约 4% 通过率，东财被网络层掐断） | 1 个交易日 |
| **B 宏观政策** | TACO 水平/分位/条件概率/主导因子；地产四件套（70城同比、BIS 周期、30城高频、上涨城市数） | `ocmacro-feed/ocmacro_feed.py digest --json` | 沙箱/本机皆可（纯标准库） | 1 个交易日 |
| **C 事件日历** | 未来 7 天：FOMC / CPI / PCE / 非农 / EIA / OPEC / 财报 / 解禁 / 社融 / PMI | WebSearch + `anthropic-fs-skills/catalyst-calendar` 方法论 | 沙箱（automation） | 1 个交易日 |
| **D 新闻热点** | 财经 / 国际 / AI 三路各 top 10，去重后保留时间戳与来源 | `news-aggregator-skill` + `mx-search` + WebSearch | 沙箱（automation） | 1 个交易日 |
| **E 政策与地缘** | 近 7 天政策文件原文要点、地缘事件、央行与部委动向 | `mx-search`（权威优先）+ WebSearch | 沙箱（automation） | 7 天 |

⚠️ **层 A 与层 B–E 必须分开跑**：层 A 是数值抓取、受沙箱限流；
层 B–E 是网页与研究、沙箱内可用（**沙箱掐的是行情接口，不是网页**）。
把两者塞进同一个任务，会因层 A 失败而让整包降级——**这是本规范最重要的工程约束**。

### 2.4 降级与失败

- **层 A 失败**：背景包仍生成，`A_market.status = "missing"` + `reason` 写明
  「沙箱限流，需本机 crontab 补跑」。**不得用记忆旧值或上一次的收盘价冒充当日**。
- **层 B–E 单层失败**：该层标 `missing`，其余层照常。`overall = "partial"`。
- **全部层失败**：仍要落盘一份 `overall = "failed"` 的包——
  **「有包但全失败」是可诊断的，「没有包」是不可诊断的**。
- 任何降级都必须在报告里显式出现，**禁止静默**（沿用框架既有纪律）。

## 三、新鲜度闸机

执行器：`market-data-cache/freshness_check.py`（Q-T2 的机器化，2026-10-15 立）。

```bash
cd "$CAISEN_ROOT"
python3 market-data-cache/freshness_check.py                 # 体检报告（只报告不拦截）
python3 market-data-cache/freshness_check.py --require-fresh  # 阻断级不达标 → exit 2
python3 market-data-cache/freshness_check.py --auto-refetch   # 对可重跑项自动重跑
python3 market-data-cache/freshness_check.py --json           # 机读
python3 market-data-cache/freshness_check.py --now "2026-10-09T17:00"   # 回溯体检
```

**判据（Q-T1 数据日确认的机器化）**——「此刻应当能拿到的最新数据日」：

| 情形 | 期望数据日 |
|---|---|
| 今天是交易日 且 当前 ≥ 16:00（已收盘） | **今天** |
| 今天是交易日 且 当前 < 16:00（盘中） | **上一交易日**（今日尚未收盘） |
| 今天不是交易日（周末/节假日） | **上一交易日** |

数据日 < 期望数据日 → `stale`（并报「落后 N 个交易日」）；无产物 → `missing`。

**严重度**：`briefing` 与 `market_cache` 为 **block**（缺失即阻断）；
`ocmacro` 等为 **warn**（允许降级为分析时实时补拉）。`--strict` 可把 warn 全部升级为阻断。

**交易日历**：`market-data-cache/trade_calendar.json`（westock-mcp `data_trade_calendar`
实测导出，2026 全年 242 个交易日）。超出 coverage 时脚本**自动降级为「仅排除周末」并在输出中标注**，
不静默——但需注意此时节假日可能误判，**跨年时须重新导出日历**。

## 四、消费规则（12 专家怎么用）

1. **开工第一件事**：`freshness_check.py --require-fresh`。不过关不许进入第0.8步及以后。
2. **读包不重取**：背景包已有的层，**不得再各自实时抓一遍**——那是重复 I/O，
   也是「12 专家各拿一份不同口径背景」的根源。只对**背景包未覆盖的标的一侧**做实时补拉。
3. **遵守切片分发**：背景包是全量料，**分发时按 SKILL.md 第-0.4步的切片表投喂**——
   例如宏观叙事不给蔡森/Mi姐，地产细节不给路口大爷。**给全量 = 破坏独立性原则**。
4. **回溯不倒灌**：背景包的 `date` 早于分析日时，其内容**只能作为历史快照引用**，
   须标注明数据日；**禁止用早于分析日的读数论证当前趋势**（M-Y5 事件传导窗口错配律）。

## 五、生成流程（定时任务）

**任务 A · 层 B–E 预取（沙箱，automation）**：每交易日 16:00 后触发，产出
`_runs/briefing/<当日>.json` + `.md`。取数顺序：B（脚本，秒级）→ C（事件日历）→ D（新闻）→ E（政策）。
完成后**自跑** `freshness_check.py` 并把结果写进包尾。

**任务 B · 层 A 行情预取（本机，crontab）**：因沙箱限流，**必须在能直连行情源的机器上跑**：

```cron
# 每交易日 16:10 拉当日行情缓存（周一至周五；节假日脚本内部自判）
10 16 * * 1-5 cd "$CAISEN_ROOT" && python3 market-data-cache/fetch_daily.py --force >> /tmp/caisen_fetch.log 2>&1
```

首次配置后**必须验证 `market-data-cache/cache/` 下真的出现了 `<日期>.json`**——
`--help` 通过不等于能跑通（框架 2026-09-20 已因此栽过一次，见 SKILL.md 第0步第7条纪律）。
